## 本地 JS Playground（js-playground.html）

**需求**：双击打开、离线、带语法高亮 + 代码提示的 JavaScript 编辑器。

**选型结论**：不能用 Monaco。两条硬原因——TS 语言服务跑在 Web Worker，`file://` 下 origin 为 null 无法创建 Worker；AMD 构建动态加载多文件，塞不进单 HTML。
改用 **CodeMirror 5.65.21**：UMD 单文件、无 Worker、`file://` 下直接可用，内置 show-hint + javascript-hint。

**产物**：
- `js-playground.html`（约 508 KB，完全自包含，0 外链）
- `_build/app.template.html` 源模板 + `_build/build.mjs` 构建脚本（把 CM5 的 js/css 内联到占位符）
- 改样式/逻辑：改 template 后跑 `node build.mjs` 重建

**已实现**：
- 高亮、行号、括号匹配/自动闭合、当前行高亮、可拖拽左右分栏
- 补全：Ctrl+Space 手动 + 键入自动（120ms debounce）。覆盖内置 API 白名单、文档内声明变量、对象字面量属性、数组/DOM/console 成员
- 运行：sandbox iframe（allow-scripts，不带 same-origin）+ postMessage 回传 console，每次运行重建 iframe 保证干净全局环境
- 顶层 await 可用（async 包装）
- 3s 超时强制终止
- localStorage 自动保存草稿、导出/导入 .js

**关键修复**：CM5 5.65 的原生 `javascript-hint` 里 `state.localVars` 为空，且默认 `useGlobalScope` 会枚举整个 window 产生巨量噪音。做法：关掉 `useGlobalScope`，用正则自行收集声明，通过 `additionalContext` 注入内置对象实例（console/Math/document/localStorage 等）来恢复成员补全。

**验证方式**：Chrome 154 headless + CDP（WebSocket 直连 9222）。覆盖 demo 输出、warn/error 分级、语法错误、运行时错误堆栈、超时终止、四类补全、外链数量 = 0。

**已知限制**：
- 同步死循环 `while(true){}` 会卡死标签页，3s timer 无法介入（iframe 同进程，无法抢占）
- 补全是词法/正则级，非 TS 语义级；无跨文件、无类型推导、无 node_modules 类型
- 无断点调试

**环境**：Node v22.22.2 / npm 10.9.7；CM5 装在 `_build/node_modules`（3.6 MB）

## 追加：语法检测（lint）

品牌副标题「本地离线 · CodeMirror 5」→「本地离线 · Teddy 出品」。

**需求**：漏括号（如 `console.log(...` 少一个 `)`）要能立刻看到提示，不能等运行时才报。

**方案**：内联 **acorn 8.19.0**（`dist/acorn.js`，MIT，241 KB）做真解析，不用正则猜。

- `parseCode()`：`ecmaVersion: "latest"` + `allowAwaitOutsideFunction` / `allowReturnOutsideFunction` / `allowHashBang`；遇 `sourceType: module` 报错再按 module 重试一次（支持 `import`）。
- `scanBrackets()`：用 `acorn.tokenizer` 遍历 token 做括号栈。注释/字符串/模板/正则都按真实词法处理，不会被 `/[)]/` 里的括号骗到。
  - 解析器只会说 `Unexpected token (7:0)`，指向崩掉的那行；括号栈能反推出**真正缺的那一边**，所以对 `Unexpected token` / `Unexpected end of input` / `Expecting` 这类模糊错误优先用括号栈的定位。
  - 三种诊断：`missing`（缺右括号，定位到开括号）、`extra`（多余闭括号）、`unclosed`（到 EOF 都没闭合）。
- **全角符号专项**：错误位置的字符若落在全角区（U+FF01–FF5E、U+3000、U+2018–201D、U+3001–3011），直接说「全角符号 ，，应改成 ,」，用 `charCode - 0xFEE0` 算半角对照。中文输入法下最常见的坑。
- `MSG_ZH` 正则表把 acorn 英文消息翻成中文（约 25 条），匹配不到就回落原文。

**UI**：
- gutter 新增 `lint` 列（`gutters: ["CodeMirror-linenumbers", "lint"]`），红点 7px，`title` 挂详情
- 错误位置到行尾 `markText` + `.cm-lint-underline`（`text-decoration: underline wavy`）
- 状态栏「语法检查通过」（绿）/「缺少右括号 ) · 第 6 行」（红，点击跳转）
- 点「运行」时若仍有语法错误，输出面板先插一条 `SYS 语法错误 · 第 N 行：…（仍尝试执行）`，不阻止执行（避免 acorn 对更新的语法误判导致无法运行）

**实测**（Chrome headless + CDP）：漏括号 → 定位第 6 行第 14 列的 `(`；未闭合字符串/大括号/方括号、多余闭括号、全角括号与中文引号、严格模式参数重名、顶层 await、import、class 字段、正则里的括号、模板嵌套、注释里的括号，全部判断正确。1500 行解析 11 ms。demo 运行仍 5 行输出、补全 `cons` 仍正常、页面无异常。

体积 760 KB（acorn 占 241 KB）。

## 追加：注释 / 取消注释

内联 CM5 官方 `addon/comment/comment.js`（9 KB），不需要自己写字符串处理。JS mode 自带 `lineComment: "//"` + `blockCommentStart: "/*"` 配置，addon 直接读得到。

**入口**：`Ctrl+/`（以及 `Cmd+/`）+ 编辑区标题栏右侧的小按钮「注释 Ctrl+/」。

**关键坑**：`CodeMirror.commands.toggleComment` 是 `cm.toggleComment()` 的无参包装，**传不进 options**。所以快捷键和按钮都不能用 `execCommand('toggleComment')`，必须直接调 `cm.toggleComment({indent:true, blockCommentLead:" * "})`：
- 不带 `indent:true` → `  console.log(1)` 变成 `//   console.log(1)`（`//` 顶到行首，原缩进变正文）
- 带上之后 → `  // console.log(1)`，且多行按最小公共缩进对齐
- `blockCommentLead` 是给 `/* */` 多行用的续行前缀（mode 里声明的是 `blockCommentContinue`，addon 读的是 `blockCommentLead`，名字不一致，得手动补）

**行为**（实测）：单行/多行选区/含空行选区都能注释并完整还原；一次操作 = 一步 undo；选中到下一行行首（ch=0）时那行不计入，与 VS Code 一致。

**已知**：光标在模板字符串内部时，`//` 会被当正文插入（CM 的 `probablyInsideString` 守卫在多行模板的内部行失效，因为 `getTokenTypeAt` 返回 null）。VS Code 同样插入字面 `//`，不改。

体积 771 KB。

## 追加：顶栏「注释 / 取消注释」两个按钮

原来的注释入口是编辑区标题栏的小按钮（切换式）+ Ctrl+/。改成顶栏两个**独立**按钮，避免有人不知道快捷键：

| 按钮 | 行为 | 悬停气泡 |
|---|---|---|
| 注释 | 只加 `// `，已注释的行跳过 | 添加行注释 · Ctrl+/ 可切换 |
| 取消注释 | 只删 `//`，脚本按行处理（不要求全选区都已注释） | 移除行注释 · Ctrl+/ 可切换 |

`Ctrl+/` 保持「切换」语义不变，作为快捷方式并存。

实现要点：
- 没用 CM 的 `uncomment`（它要求整个选区都带注释，否则一行都不动）；自己写逐行处理：
  - 加注释 `^(\s*)` 取缩进 → 在缩进后插 `// `；`\S` 判空行跳过
  - 去注释 `/^(\s*)\/\/ ?/` 删 `//` + 一个可选空格；兼容手写的 `//no-space`；顺带支持单行 `/* x */`
- 一次点击包在 `cm.operation()` 里 → 一步 undo；状态栏回报「已注释 N 行 / 这几行已经注释过了」
- 空行不算改动，混合选区只处理带 `//` 的那几行

**悬停提示**用 CSS `[data-tip]:hover::after`，不是原生 title（无 1s 延迟）。注意 `content:attr(data-tip)` + `translateX(-50%)` 居中，z-index 200。

**窄屏**：加了两个媒体查询——`max-width:860px` 隐藏自动保存时间戳、`max-width:760px` 隐藏 `kbd` 并收窄按钮 padding。实测 1300/1100/1000/900/820/760/700px 均无溢出（此前 820px 就溢出 46px）。

体积 773 KB。

## 转 Bookmark JS（22:45）
- 入口在**编辑区标题栏**（`#bmBtn`，`data-tip` 提示 + `Alt+Shift+B`），不在顶栏：顶栏 10 个按钮在 1100px 就会溢出，塞第 11 个必然崩。
- 核心约束：书签链接只能一行，浏览器执行前会对整串**百分号解码一次**（headless Chrome 154 实测：`%0A`→换行、`%23`→`#`、`%25`→`%`、`%20`→空格、中文原样）。因此 `%` 和 `#` 必须转义，模板字符串/多行注释里的换行只能写成 `%0A`。
- 生成流程：`acorn.tokenizer`（`onComment` 收集注释）→ token/注释合并成一条有序序列 → 逐项拼接：
  - `//` 行注释改写成 `/* */`（失去换行会吃掉后面所有代码），注释里出现 `*/` 时替换成 `* /`；
  - 删掉的换行按 AST 的**语句结束位置**补 `;`（`bmStmtEnds` 只认 ExpressionStatement/VariableDeclaration/Return/Throw/Break/Continue/Debugger/DoWhile/PropertyDefinition/Import·Export，**排除 BlockStatement**，否则会在 `try{}catch` 前插分号）；
  - 相邻 token 用已有的 `needSpace()` 防粘连。
- **AST 对拍兜底**：生成结果重新 `acorn.parse` 与原文比对（`bmCanon` 去掉 start/end/loc/range），不一致就退回保守模式 `bmEsc(原文)`（换行全走 `%0A`，语义绝对等价）。22 个用例（ASI 陷阱、class 字段、do-while、模板换行、正则 `%20`、中文 `#`）全部 AST 一致。
- 包裹：默认 `(function(){…})();void 0`，`void 0` 防「完成值非 undefined 导致整页被替换」；取消勾选则 `javascript:body;void 0`。
- 弹窗 `.bm-veil/.bm-card`（z-index 90）：只读 textarea 按内容自适应高度（clamp 70–220px）、`overflow-wrap:anywhere` 换行；底部「拖我到书签栏」（`<a href="javascript:…" draggable>`，click 时 preventDefault）、「还原为代码」、「复制链接」（`execCommand('copy')` 失败再退 `navigator.clipboard`）。
- **往返闭环**：弹窗「还原为代码」或「当前内容已以 `javascript:` 开头时再点按钮」→ `bmUnwrap`：去前缀 → 解码 → 去 `void 0` → 头尾正则配对才拆 IIFE → `js_beautify` 重排 → 行尾 `/* x */` 还原成 `// x`。
- 语法错误时照旧 `blockOnSyntax()` 拦截并定位；`import/export` 直接拒转。
- 顺带修顶栏响应式：`.brand` 加 `nowrap`（700px 曾折成两行）、断点阶梯改为 `1180 缩内边距 / 1000 隐状态 / 940 隐 kbd 与品牌副标题 / 880 / 780 / 760 缩间距`，实测 700–1440 无溢出。
- 实测：1500 行（27.8KB）转换 53ms；生成结果用 `location.href = javascript:…` 真跑一遍，`["ok",3,"a%20b#c","100%"]` 与预期完全一致。体积 1004 → 1022 KB。
- 测试留在 `_build/test-bookmarklet.cjs`（Node 单测 22 例 + 往返）与 `_build/e2e-bookmarklet.mjs`（CDP 端到端、含截图）。

## 模拟页面 DOM（23:05）
- 用户问「能不能针对某个网页 DOM 运行」。结论：**编辑器内的「运行」做不到**——跨标签页无 DOM API；iframe 嵌外站跨源不可读且多数站点 `X-Frame-Options`/CSP 拒绝；`sandbox="allow-scripts"` 无 `allow-same-origin` 是 opaque origin。真正能打真实站点只有书签 JS / DevTools 粘贴 / UserScript 三条路。
- 用户选了「只做沙箱注入 HTML」：输出面板标题栏加 `#mockBtn`（激活态 `.pane-btn.is-on`），展开 `.mock-panel`（`#mockCode` textarea + 示例/清空 DOM）。
- 数据流：`run()` 里 `pendingHtml = mockValue()` → `postMessage({__jsplay_cmd:"run", code, html})` → 沙箱收到后**先** `document.body.innerHTML = ''`，再用 `new DOMParser().parseFromString(src,'text/html')` 取 `parsed.body.innerHTML` 注入，**然后**才 `new Function` 执行用户代码。
  - 用 DOMParser 而非直接拼 srcdoc：不用转义、贴完整 `<html>` 也能取出 body、`<script>` 天然不执行（实测 `data-ran` 为 null）。
  - 每次运行都重置，避免上一次运行的节点污染（实测第二次跑 `again 3 null`，属性没残留）。
  - 内联事件（如 `<img onerror>`）仍会触发，属沙箱内行为，可接受。
- 持久化 `js-playground.mock.v1`（400ms 防抖），刷新后恢复内容与按钮激活态（面板保持收起）。
- 快捷键 `Alt-M`；`mockSub` 实时显示「已启用 · N 字符 · 运行时会注入沙箱」。
- 顺带：`.pane-head [data-tip]::after` 加 `max-width:min(300px,72vw);white-space:normal`，否则长气泡被 `.pane{overflow:hidden}` 裁掉；`≤760px` 时 `.mock-code{height:min(15vh,104px)}`。
- 「清空」重名问题：输出面板的「清空」与模拟页面的「清空」并排易误点，后者改叫「清空 DOM」。
- textarea 用 `white-space:pre-wrap` + `overflow-wrap:anywhere`，超长单行 HTML 折行显示（原本 `pre` 需要横向滚动）。
- 实测：500 节点/46KB → 13ms；2000 节点/189KB → 19ms；8000 节点/770KB → 57ms。700px 窄屏标题栏溢出 0，输出区剩 140px。
- 测试：`_build/e2e-mock.mjs`（12 组用例 + 三张截图）。

## 控制台 REPL（23:20）
- 需求：跑完还能在输出面板敲 `users.length` 求值，像 DevTools。
- 核心障碍：原来每次 run 都是 `resetFrame()` 重载 iframe + `new Function` 新作用域，变量必然随函数退出而销毁。要保留上下文，必须做两件事：
  1. **iframe 变持久会话**：`frameState = idle|loading|ready`，只首次 run 时设 srcdoc，之后全走 postMessage。顺带每次运行快了 30–60ms。
  2. **顶层声明显式搬运**：`buildExports()` 用 acorn 扫 `Program.body` 的 VariableDeclaration / FunctionDeclaration / ClassDeclaration（含解构 Pattern 递归、rest、默认值），生成 `try{__c.x=x}catch(e){}` 追加到用户代码末尾，写进沙箱的 `CTX`。
- 为什么不能直接 `(0,eval)(code)` 保上下文：整份脚本连续跑两次会撞 `Identifier 'a' has already been declared`。用「独立函数作用域 + 主动导出」才是既支持重跑又保留上下文的正解。
- `new Function('__c', body)` 必须把 CTX 当**形参**传进去——body 在全局作用域执行，看不到闭包里的 CTX（踩过这个坑，exports 全静默失败）。
- 求值：`with(__c){ return (async () => (\n expr \n))(); }`，先表达式后语句块；两侧补换行，否则源码末尾的 `//` 会把收尾括号注释掉。
- 语句模式也带 exports，所以 `var z = 5` 之后 `z` 还能用（`z*2` → 10）。
- 显示：`fmtVal` 走紧凑 JSON（`["Ada","Alan"]`），字符串带引号，`#document` / `Window` / `<div#id.class>` 特判；错误只留 `Name: message` 一行，REPL 的栈全是 with 内脏没意义。
- UI：`.repl-bar` 常驻输出面板底部（`›` 前缀 + 34px），`›` 输入行 faint 色、`‹` 结果行 accent 色，无边框衔接成一组。↑/↓ 历史、Esc 清空失焦、Enter 求值。
- 每次 run 都重置 `CTX = Object.create(null)` 和页面 DOM = 新会话；重跑同一份代码实测无重复声明报错。
- **教训**：改完 `app.template.html` 必须 `node _build/build.mjs` 再测。中途漏了构建，拿旧产物测出 `var z` 失败的假阳性，白排查半小时。
- 测试：`_build/e2e-repl.mjs`（15 个表达式 + 重跑 + 顶层 await + DOM 保持 + 历史 + 窄屏）。

## 同名标识符高亮（23:45）
- 需求：像 VS Code 那样双击/选中一个变量，文件里其余同名处用浅色底标出来。
- **没用内置的 `addon/search/match-highlighter.js`**（`highlightSelectionMatches`）：它走 `addOverlay`，只能染一种颜色；边界判定写死 `\w`，`$foo` 和中文标识符直接失效；也没法区分「代码里的引用」和「注释/字符串里的同名词」。改为自己用 `markText` 标。
- 定位：`occTarget()` 取 `listSelections()[0]` 的 anchor/head，向左右按 `[\p{L}\p{N}_$]` 扩到完整标识符，再校验 `/^[\p{L}_$][\p{L}\p{N}_$]*$/u`。所以选中半个词（`use`）会自动补成 `users`，光标停在词尾也能取到整个词；跨行选区、选中空格/数字/标点都返回 null。
- 扫描：逐行 `indexOf` 快速跳过，`new RegExp(esc,'gu')` + 手写前后字符边界（不能用 `\b`，`$` 不在 `\w` 里）。`OCC_MAX=1200` 截断，防止单字符变量在大文件里把页面拖死。
- 三档颜色由 `getLineTokens(ln, true)` 的 token 类型决定：当前处 `cm-occ-here`、代码里的引用 `cm-occ-hit`、`comment|string|regexp` 里的同名词 `cm-occ-soft`。
- **踩的坑（关键）**：第一版用蓝色 `rgba(120,162,228,.32)`，白底混合后是 `#D4E1F6`，而编辑器选区是 `#CFE1F7`——只差几个色阶，肉眼完全分不清「我选中的」和「其他出现」，等于没做。改**青绿 (teal)** 后色相拉开才成立。深色主题同理，背景 `rgb(22,26,32)` 上 .16 的 alpha 太弱，提到 .28 才看得见。
- 与查找面板互斥：`srchState.open` 时 `occClear()` 并跳过扫描（那边用黄色 `cm-srch-hit`，两组叠加会花）；`openSearch` / `closeSearch` 里分别清掉、`occSchedule()` 接回来。
- 调度 `cursorActivity` + `changes` 都走 110ms 防抖。实测 800 行 / 1600 处同名：截到 1200 个 mark，重建 134ms（含 110ms 防抖，实际开销约 24ms）；20 次连续 setCursor 不堆积 mark。
- 验证：真实鼠标双击（`Input.dispatchMouseEvent` clickCount:2）选中 `data` → 3 处标记（前后各一处 hit + 当前 here）；折叠、格式化（整体替换文档）、注释切换后均正常重扫；`errors: 0`。
- 测试留在 `_build/e2e-occ.mjs`（光标 / 双击 / 半词 / `$` / 中文 / 空白 / 跨行 / 查找共存 / 编辑后 / 1200 mark 性能 + 三张截图）。

  4. `Ctrl+Shift+L` 本来就在 document keydown 里实现了（`if (e.shiftKey) { if (k === "l") toggleTheme() }`），我又往 extraKeys 加了一份，结果焦点在编辑器里时**触发两次互相抵消**，主题纹丝不动。删掉 extraKeys 那份即恢复。教训：加快捷键前先搜一遍有没有非 extraKeys 的实现。
